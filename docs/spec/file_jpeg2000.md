# JPEG 2000 (`imgio::file::jpeg2000`, feature `jpeg2000`)

Decode only, via `hayro-jpeg2000` 0.5.0 (pure Rust, `default-features = false`,
`features = ["simd"]`: `fearless_simd` only; no `image` / `moxcms`). No pure Rust encoder
exists: `encode` returns `Unsupported`.

- Input: JP2 files and raw J2K codestreams (`FileFormat::detect`: JP2 signature box or
  `FF 4F FF 51`).
- Coding: 5/3 reversible and 9/7 irreversible wavelets, RCT / ICT, tiles (with offsets),
  quality layers, all progression orders, image area offsets, palettes (resolved), sYCC
  (converted to RGB in f32 by hayro).
- API: `decode`, `decode_with(data, &DecodeOptions { reduce, max_pixels })`, `info` (full-size
  dimensions, channels, alpha, bit depth, codestream vs JP2). `reduce` skips the highest
  resolution levels (size halves per level, rounded up; clamped to the levels present; passed
  to hayro as `target_resolution = (w >> r, h >> r)`). `max_pixels` (default 2^26) bounds the
  full-resolution size before any pixel allocation (`Unsupported` above).
- Sub-sampled components: upsampled by hayro with sample replication (each sample covers its
  `XRsiz x YRsiz` reference-grid area, nearest neighbour). Three components with sub-sampled
  chroma in a raw codestream are treated as YCbCr (sYCC). Equal sub-sampling on every
  component decodes at the reduced size.
- Output: <= 8-bit components -> `R8Unorm` / `Rg8Unorm` / `Rgb8Srgb` / `Rgba8Srgb`; any
  component > 8 bits -> `R16Unorm` / `Rg16Unorm` / `Rgba16Unorm` (RGB: alpha 65535). Samples
  are rounded (ties to even), clamped to `[0, 2^p - 1]` and scaled per component as
  `(v * (2^n - 1) + (2^p - 1) / 2) / (2^p - 1)` (integer; identity when `p == n`). Signed
  components come out offset to the unsigned range. ICC profiles with 1 / 3 channels are
  ignored (gray / RGB samples returned); CMYK, CIELab and other spaces -> `Unsupported`.
- Robustness: hayro errors map to `InvalidData` (`Unsupported` for its unsupported-feature
  and too-large errors). hayro is `forbid(unsafe_code)` but has internal `unwrap` / `assert`;
  calls are wrapped in `catch_unwind` (-> `InvalidData`) as a guard. The truncation /
  bit-flip test (also run with 4000 flips per file) never reached it.

## Tests (`tests/file_jpeg2000.rs`, data `testdata/file/jpeg2000`)

Generated by `scripts/gen_file_testdata_jxlj2kvdb.py` (`gen_jpeg2000`) with OpenJPEG only:
imagecodecs `jpeg2k`, Pillow 13 (OpenJPEG 2.5.4: tiles, layers, progression, offsets, sYCC)
and the `opj_compress` 2.5.0 CLI (raw input with per-component sub-sampling).

- Lossless 5/3, exact vs the source: gray 4/8/12-bit, gray+alpha 8/16, RGB 8 (RCT and no MCT)
  and 12, RGBA 8/16; JP2 and J2K; tiles 32x32 + 3 layers + RPCL; tiles 16x16 + CPRL + 3 layers;
  gray + 2x2 sub-sampled alpha (exact vs replication).
- Reduce: exact vs OpenJPEG `skipres` (RGB 8-bit r1, r2; gray 12-bit r1).
- Lossy / colour converted, vs OpenJPEG's decode: 9/7 RGB, RGBA, 12-bit gray, 9/7 with tiles,
  image offset (3, 5), PCRL and 3 dB-layers, 9/7 reduce 1, sYCC JP2, YCbCr 4:2:0 codestream.
  Bound: max 1 LSB (16 in 16-bit units for 12-bit samples) and mean <= 0.5 LSB. Both decoders
  run the 9/7 inverse in f32 with different lifting order / rounding (OpenJPEG `lrintf`), and
  OpenJPEG converts sYCC with integer truncation where hayro uses f32; measured: 9/7 means
  <= 0.002 LSB, sYCC ~0.45 LSB.
- `info`, detection and `file::decode` dispatch; reduce clamping; `max_pixels` and a patched
  65536 x 65536 header -> `Unsupported`; `encode` -> `Unsupported`; truncation at ~150
  lengths and 200 bit flips per file never panic.
